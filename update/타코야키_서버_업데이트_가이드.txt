타코야키 박스 서버 업데이트 가이드 (Oracle Cloud / VM용)
=================================================

이 폴더에 함께 있는 update_script.json 파일 안에 들어있는 코드를
서버(VM)에 옮겨서 실행하면, GitHub에 올린 최신 코드로 서버가 자동으로 업데이트됩니다.

전체 과정은 딱 3단계입니다.
  1단계. 내 컴퓨터에서 서버(VM)로 접속한다.
  2단계. update_script.json 안의 코드를 서버에 파일로 저장한다.
  3단계. 그 파일을 실행한다.

준비물
------
- Oracle VM 주소(공인 IP): 161.33.166.213
- VM 접속용 SSH 개인키 파일 (Oracle에서 VM 만들 때 "Save private key"로 저장해둔 파일. 보통 .key 또는 .pem 확장자)
- VM 사용자 이름 (Ubuntu 이미지라면 보통 ubuntu)


1단계. 서버(VM)에 접속하기
--------------------------
Windows PC에서 "터미널" 또는 "PowerShell"을 엽니다.

아래 명령어를 입력하세요. <키파일경로>는 실제 개인키 파일이 있는 위치로 바꿔 넣으세요.
(예: C:\Users\내이름\Downloads\ssh-key.key)

    ssh -i "<키파일경로>" ubuntu@161.33.166.213

- 처음 접속하면 "계속 연결하시겠습니까?" 같은 질문이 나올 수 있습니다. yes 를 입력하고 엔터를 누르세요.
- 접속에 성공하면 화면이 "ubuntu@..." 같은 모양으로 바뀝니다. 이제부터 입력하는 명령어는
  전부 "내 컴퓨터"가 아니라 "서버(VM)" 안에서 실행되는 것입니다.


2단계. 코드를 서버 안에 파일로 저장하기
--------------------------------------
서버에 접속된 상태에서, 아래 명령어를 입력해 원래 서버 코드가 있는 폴더로 이동합니다.
(처음 설치할 때 git clone 받았던 그 폴더 이름입니다. 보통 tacoyaki-server 입니다.)

    cd tacoyaki-server

그다음 편집기를 엽니다.

    nano update.sh

화면이 텅 빈 편집 화면으로 바뀌면, update_script.json 파일을 열어서
"content" 항목 안에 있는 코드 전체를 복사한 뒤, 이 화면에 그대로 붙여넣으세요.
(터미널에서 붙여넣기는 보통 마우스 오른쪽 클릭, 또는 Ctrl+Shift+V 입니다.)

붙여넣기가 끝나면 저장하고 나갑니다.
    Ctrl + O  (저장)  →  엔터  →  Ctrl + X  (나가기)


3단계. 파일을 실행 가능하게 만들고 실행하기
--------------------------------------------
아래 두 줄을 순서대로 입력합니다.

    chmod +x update.sh
    ./update.sh

실행하면 화면에 [1/5], [2/5] ... 순서로 진행 상황이 표시됩니다.
중간에 비밀번호(sudo 암호)를 물어보면 VM 계정 비밀번호를 입력하세요(화면에 글자가 안 보여도 정상입니다).

전부 끝나면 [5/5] 완료! 메시지와 함께 확인 주소가 나옵니다.


확인하기
--------
아무 브라우저에서 아래 주소를 열어보세요.

    http://161.33.166.213:8787/health

{"ok":true,"ver":"..."} 에서 ver 뒤의 날짜가 오늘 날짜(또는 최근 GitHub 업데이트 날짜)로
바뀌어 있으면 성공입니다.


다음번 업데이트부터는?
-----------------------
2단계(파일 새로 만들기)는 다시 안 해도 됩니다. 다음부터는 그냥
서버에 접속한 뒤 아래 두 줄만 입력하면 됩니다.

    cd tacoyaki-server
    ./update.sh


막히면
------
- "Permission denied" 라고 뜨면 → 앞에 sudo 를 붙여서 다시 시도하세요. (예: sudo ./update.sh)
- "command not found: docker" 라고 뜨면 → 이 VM에 Docker가 설치 안 된 것입니다. 원래 서버를
  설치할 때 썼던 방법을 다시 확인해보세요.
- ssh 접속 자체가 안 되면 → 키 파일 경로가 맞는지, VM이 켜져 있는지, 방화벽에서 22번 포트가
  열려 있는지 확인하세요.
